### Архитектура: "Живое Знание" — от Хаоса к Связанному Контексту

Эта архитектура построена на трех китах: **Атомарность** (каждая единица информации независима), **Иерархичность** (информация может расти вглубь) и **Связность** (информация образует сеть, а не просто дерево).

---

#### Схема Базы Данных (PostgreSQL + pg_vector)

**1. `artifacts` — Контейнеры Знаний (Темы/Проекты/Треды)**
*   `id` (PK, UUID) — Уникальный идентификатор темы.
*   `title` (TEXT) — Человекочитаемое название, генерируемое LLM.
*   `summary` (TEXT) — "Живая суть", постоянно обновляемое резюме артефакта.
*   `summary_vector` (VECTOR) — Вектор для поиска целых тем.
*   `parent_artifact_id` (FK -> `artifacts.id`, nullable) — Для создания иерархии (погружения).
*   `source_entry_id` (FK -> `structured_entries.id`, nullable) — Указывает, какая запись породила этот дочерний артефакт.
*   `applied_schema_id` (FK -> `schemas.id`, nullable) — Какую структуру использует этот артефакт.

**2. `messages` — Атомы Разговора**
*   `id` (PK, BigInt)
*   `artifact_id` (FK -> `artifacts.id`) — В каком артефакте было это сообщение.
*   `content` (TEXT) — Текст сообщения.
*   `content_vector` (VECTOR) — Вектор для поиска по конкретным фразам.
*   `sender`, `timestamp`, и т.д.

**3. `structured_entries` — Атомы Структурированных Знаний**
*   `id` (PK, UUID)
*   `artifact_id` (FK -> `artifacts.id`) — К какому артефакту относится эта запись.
*   `data_jsonb` (JSONB) — Сами данные (`{"Задача": "...", "Срок": "..."}`).
*   `text_representation` (TEXT) — Человекочитаемая версия данных для векторизации.
*   `text_representation_vector` (VECTOR) — Вектор для семантического поиска по записям.

**4. `schemas` — "Гены" Структуры (Ваше ключевое добавление)**
*   `id` (PK, UUID)
*   `name` (TEXT) — Название, генерируемое LLM ("Шаблон Задач", "Структура Идей для Книг").
*   `description` (TEXT) — Описание назначения схемы ("Отслеживает задачи, ответственных и сроки").
*   `schema_jsonb` (JSONB) — Сама схема (`{"Задача": "string", ...}`).
*   **`description_vector` (VECTOR)** — Вектор `name` + `description`. **Это позволяет системе находить и предлагать релевантные шаблоны.**

**5. `links` — Сеть Знаний (Knowledge Graph)**
*   `id` (PK, BigInt)
*   `source_entity_type` (TEXT) — 'artifact' или 'structured_entry'.
*   `source_entity_id` (UUID)
*   `target_entity_type` (TEXT)
*   `target_entity_id` (UUID)
*   `link_type` (TEXT) — "противоречит", "поддерживает", "является примером".
*   `description` (TEXT) — Описание связи, генерируемое LLM.

### Как Это Работает Вместе: "День из Жизни Пользователя"

**1. Начало.** Пользователь начинает писать о встрече.
> "Итоги встречи по 'Ориону': решили, что запускаем 1-го октября, маркетинг должен подготовить материалы."
*   Система не находит релевантных артефактов и создает новый: `artifact` #1 ("Итоги встречи: Орион").

**2. Обучение на Примере.** Пользователь продолжает:
> "Нужно отслеживать задачи. **Задача:** Подготовить маркетинговые материалы. **Ответственный:** Отдел маркетинга. **Срок:** 25.09."
*   LLM предлагает: "Вижу структуру (Задача, Ответственный, Срок). Хотите отслеживать все задачи по этому проекту так же?" Пользователь соглашается.
*   **Происходит магия:**
    *   Создается новая запись в `schemas` #1 (Name: "Схема Задач Проекта", Schema: `{"Задача": ...}`).
    *   `artifact` #1 обновляется: `applied_schema_id` = 1.
    *   Создается первая запись в `structured_entries` #101 с данными о задаче.

**3. Обогащение ("Context Gravity").** Через час пользователь пишет в "главный" чат:
> "По 'Ориону' - бюджет на маркетинг утвержден."
*   Система векторизует фразу, находит `artifact` #1 с высоким сходством.
*   LLM отвечает: "Понял, добавляю в обсуждение по **'Ориону'**." Новое сообщение попадает в `messages` с `artifact_id` = 1. **Новый артефакт не создается.**

**4. Погружение (Иерархия).** Пользователь нажимает [💬 Обсудить] рядом с задачей `structured_entry` #101.
*   Создается **новый `artifact` #2** ("Обсуждение: Маркетинговые материалы").
*   У него `parent_artifact_id` = 1, `source_entry_id` = 101.
*   Пользователь оказывается в чистом чате для детального обсуждения только этой задачи.

**5. Прозрение (Knowledge Graph).** В артефакте #2 пользователь пишет:
> "Основная идея материалов - показать, что наш продукт в 2 раза быстрее конкурентов."
*   Система в фоне находит старый артефакт `Анализ Конкурентов`, где сказано, что "продукт конкурента X очень быстрый".
*   LLM предлагает: "Кстати, это напрямую связано с нашим **'Анализом Конкурентов'**. Хотите **связать** эти обсуждения для полноты картины?" Пользователь соглашается.
*   Создается запись в `links`, соединяющая `artifact` #2 и `artifact` 'Анализ Конкурентов'.

**6. Автоматизация (Dynamic Templating).** Через неделю пользователь начинает новый чат:
> "Начинаем новый внутренний проект 'Вега', нужно распланировать работу."
*   Система векторизует фразу "распланировать работу" и делает поиск по `schemas` по `description_vector`.
*   Она находит `schema` #1 ("Схема Задач Проекта") как наиболее релевантную.
*   LLM предлагает: "Начинаем новый проект. Хотите сразу использовать уже знакомую нам **структуру для отслеживания задач**?"
*   Пользователь соглашается, и новый `artifact` #3 ('Проект Вега') сразу создается с `applied_schema_id` = 1, готовый к структурированию задач без дополнительного обучения.

Эта архитектура элегантно решает все поставленные задачи. Она гибкая, масштабируемая и, что самое главное, построена вокруг естественного диалога, пряча всю свою сложность "под капотом" и предоставляя пользователю опыт общения с по-настоящему умным ассистентом.
